# W5-02 — Nightly consolidation

**Status:** done
**Phase:** W5 — Proactivity + consolidation
**Depends on:** W4-01, W12-04, W12-09
**Flags:** none
**Handoff refs:** §6 W5 ⚑, §5 memory #4

## Goal

A nightly (03:00) consolidation job exists: an Agent SDK session merges/organizes `~/Kahya/memory/*.md` and the result is git-committed under strict commit discipline — but for the first 2 weeks only as a **suggested diff** the user approves from the CLI. Consolidation writes only markdown+git; kahyad triggers the SQLite reindex afterwards. Hot-window/detail-atom rules from §5 memory #4 are enforced.

## Context you need

- HANDOFF §6 W5 (verbatim, all three ⚑ bind this task):
  > gecelik konsolidasyon (bir Agent SDK oturumu markdown'ı birleştirip git-commit eder — **yalnız markdown+git'e yazar, SQLite reindex'ini kahyad tetikler**)
  > ⚑ **Konsolidasyon ilk 2 hafta öneri-modunda:** diff üretir, kullanıcı onayıyla commit eder; otomatik commit W7 mini-eval yeşiliyle açılır.
  > ⚑ **Commit disiplini:** konsolidasyondan önce kirli working tree `author=user` commit'i olur (user_edit tier git author'dan türetilir); daemon değişiklikleri daima `author=kahyad` ayrı commit; çelişkide user_edit kazanır (daemon o gün kullanıcının dokunduğu satırları atlar).
- HANDOFF §5 memory #4 (verbatim):
  > **90+ gün sıcak pencere + ayrıntı-atomu:** 48 saat değil ≥90 gün. Soğutmadan önce sayı/tarih/alıntı/karar/söz'ler yapılandırılmış olgulara terfi. Her özet **ham kanıttan** üretilir, asla alt-özetten.
- Backup tie-in, HANDOFF §6 backup ⚑: "(1) `~/Kahya` → private git remote; W5 gecelik commit'in sonuna `git push`". W4-06 owns the push machinery; this task must invoke it at the end of a successful nightly run.
- Secret-lane routing, HANDOFF §4 ⚑ (binds which model sees which file):
  > ⚑ **Sıralama değişmezi:** *Hiçbir bayt, gizli-şerit sınıflandırması yerel/deterministik olarak tamamlanmadan bulut modele gitmez.* policy.yaml globları **yalnız dosya yolları** için
  Memory files are path-addressed, so classification is deterministic via the policy.yaml secret-lane globs (W3-01). Files matching those globs may only be consolidated by the local `Qwen3-30B-A3B` lane (W3-08); if the local model cannot load (memory pressure), those files are **skipped fail-closed with a Turkish notice — never sent to cloud**. Non-secret-lane consolidation uses `claude-haiku-4-5` (§4 routing row "Çıkarım · geri-yazım"); routing decided in Go, worker obeys the envelope.
- Prior outputs: W4-01 scheduler; W12-04 corpus indexer (`kahya reindex`, kahyad sole brain.db writer); W12-09 worker harness; W12-05 memory MCP. Scheduling per §4 ⚑: launchd `StartCalendarInterval` (missed-during-sleep runs once on wake), never in-daemon cron for wall-clock.
- Mechanics chosen here (canonical, do not redesign): consolidation runs in a temporary **git worktree** of `~/Kahya` on branch `kahya/consolidation-YYYYMMDD`; the suggested diff is `git diff main...<branch>`. Approval merges the branch to main (`--ff-only` after rebase) with `--author="kahyad <kahyad@kahya.local>"`. User pre-commit uses `--author="user <user@kahya.local>"`; the W12-04 indexer derives `source_tier=user_edit` from that author.
- Pending-diff collision (canonical): if the nightly run starts while a previous suggestion is still pending (neither approved nor rejected), the old branch/worktree is deleted, a `consolidation.superseded` event is ledgered with both trace_ids, and the run regenerates against current `main`. A stale pending diff is never auto-approved and never merged.

## Deliverables

- `kahyad/internal/consolidation/consolidation.go` — orchestrator: pre-commit dirty tree as user, spawn session(s), collect edits in worktree, enforce user-line skip rule, produce diff, suggestion/auto mode switch, trigger reindex, invoke nightly `git push`.
- `kahyad/internal/consolidation/hotwindow.go` — ≥90-day hot-window selection + detail-atom promotion: numbers/dates/quotes/decisions/promises extracted to candidate facts written through kahyad's fact-write path as `source_tier=agent_derived` (quarantined; hardened by W5-04). Summaries generated only from raw episode/chunk evidence, never from prior summaries.
- Worker: consolidation session profile in `worker/` (prompt: merge duplicates, fix headings, fold new notes into topic files; output = file edits, no direct git access; session tool surface limited to a scratch-dir fs write provided by kahyad).
- Scheduler registration: `nightly-consolidation` at 03:00 via W4-01.
- CLI: `kahya consolidation show` (render pending diff), `kahya consolidation approve` (Turkish confirm prompt: `onayla`), `kahya consolidation reject`. Pending state stored in `tasks`/`events`.
- Config: `consolidation.auto_commit` (default `false`); kahyad **refuses** `true` unless an `eval.mini.pass` event (written by the W7 mini-eval, W78-01) exists in the last 30 days.
- Tests: `kahyad/internal/consolidation/*_test.go` — commit discipline, user-line skip, secret-lane file never in cloud envelope, markdown+git-only writes, hot-window promotion on synthetic >90-day fixtures.

## Steps

1. Read HANDOFF §6 W5 + backup ⚑, §5 memory #4, §4 routing/ordering invariant. Inspect W12-04 indexer and W4-01 scheduler APIs as built.
2. Implement the pre-run guard: if `~/Kahya` working tree is dirty, commit everything as `--author="user <user@kahya.local>"` with message `user edits before consolidation`.
   **Post-review note (FIX-P-1):** "everything" is the memory directory only: the guard stages `memory/**` (`git add --all -- :(literal)memory`) and commits it with `git commit --only`, so backup snapshots, other ~/Kahya files and anything the user staged by hand are never committed. Before staging it re-ensures the backup dir is git-ignored, and it refuses the night (`consolidation.backup_dir_staged` + Turkish notice) while any backup-dir path is staged. The kahyad worktree commit (step 7) stages `memory/**` the same way. A `memory_dir` that is not a subdirectory of `kahya_dir` is refused.
   **Post-review note (FIX-P-24, decision G06-4):** before this guard (before the gitignore write or any staging) the run checks the repo state with read-only git: `~/Kahya` must be on `main` (not a detached HEAD, not another branch), with no merge/rebase/am/cherry-pick/revert/bisect in progress (`MERGE_HEAD`, `REBASE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `rebase-merge`, `rebase-apply`, `BISECT_LOG`) and no unmerged index entries. Otherwise nothing is touched (a conflicted file is never staged as resolved or committed with its markers as a user edit): `consolidation.repo_state_unsafe{head, detached, in_progress, unmerged, reason}` plus the Turkish notice `Hafıza deposu (~/Kahya) beklenmedik git durumunda — konsolidasyon atlandı; 'git -C ~/Kahya status' ile kontrol et`, on every night the state persists. `kahya consolidation approve` runs the same check first; a refusal keeps the pending suggestion and its branch (the --ff-only merge would otherwise advance whatever is checked out instead of `main`).
3. Compute the user-touched line set for the day (diff of all `author=user` commits since 00:00 local). Partition memory files by policy.yaml secret-lane globs into cloud-lane and local-lane sets.
   **Post-review note (FIX-P-2, P-2-E1):** the changed-file list comes from `git diff --name-only -z` (the plain form C-quotes non-ASCII names such as `günlük.md`, and the quoted string then matched no file, silently dropping the protection); each per-file diff uses a `:(literal)` pathspec (a note named `n[ab].md` must not pull in `na.md`'s hunks); map keys and the orchestrator's lookup are both `NormalizePathKey` (forward slashes + NFC), while files are still written under their on-disk name.
4. If a pending suggestion exists, supersede it per the collision rule in Context (delete branch/worktree, ledger `consolidation.superseded`). Create the worktree + dated branch. Spawn the consolidation session(s) per lane (envelope model: `claude-haiku-4-5` cloud lane / `Qwen3-30B-A3B` local lane; local unavailable ⇒ skip lane, notify `"yerel model için bellek yok — gizli-şerit dosyaları bu gece atlandı"`). The session receives file contents and returns whole-file rewrites; kahyad writes them into the worktree only.
   **Post-review note (FIX-P-7, decision G06-3):** a lane's rewrite may only name files from that lane's own input. A key outside it (e.g. a cloud rewrite naming a secret-lane path while the local lane is skipped) rejects the whole night: `ErrRewriteUnknownPath`, nothing written, branch/worktree removed, `consolidation.rewrite_rejected{lane, reason}` (the path stays in the local ledger) and the Turkish notice `Konsolidasyon bu gece iptal edildi — model kendisine verilmeyen bir dosya yolu döndürdü` (no file name). Both production sessions enforce it in `parseRewriteResponse`; the orchestrator re-checks each lane and the merged set.
   **Post-review note (FIX-P-12, P-12-E1, decision G06-5):** right after the supersede, and before the worktree is created, the run sweeps every other `kahya/consolidation-*` branch (`for-each-ref refs/heads/kahya/consolidation-*`; an earlier auto-mode merge failure, a failed pending ledger write or a process killed mid-run leaves one with no ledger trail, and the same-day re-run would die on `branch already exists`). Each orphan's worktree is removed with `git worktree remove --force --force` (a locked registration, e.g. from a `git worktree add` killed half-way, is removed too) and its branch deleted, ledgered as `consolidation.orphan_cleaned{branch}`; a branch that cannot be deleted fails the run closed. The prefix is reserved for this job, so there is no author check on the branch tip.
   **Post-review note (FIX-B-5 phase 0):** right after the lane partition every night ledgers each lane's size, both lanes, an empty lane included: `consolidation.lane_stats{lane, files, bytes, est_tokens, largest_file, largest_bytes}` (JSONL `consolidation_lane_stats`). `est_tokens` is the conservative estimate the batch budgets use: 1 token per 2 bytes of the JSON-encoded path and content, +8 per file (Haiku 5.5's tokenizer counts about 30% more tokens than Haiku 4.5's ~3 bytes per token on Turkish text).
   **Post-review note (FIX-B-5 phase 1, decisions G06-7, G06-8):** a lane is no longer one whole-lane call. After the partition each lane's files are ordered (changed since the last `consolidation.approved` merge_commit first, then their same-directory neighbours, then the rest by commit time from one `git log --name-only -z` pass) and packed greedily into batches under the lane's budget, never splitting a file; each batch is one session call (a fresh worker per cloud batch). Config: `consolidation_cloud_batch_token_budget` 24000 (claude-haiku-5-5: a full rewrite fits the pinned CLI's 32000-token output cap with room for thinking; the prompt stays far below the 100K-token price tier; max 90000), `consolidation_local_batch_token_budget` 5000 (Qwen's `localMaxTokens` 8192; max 23000 for its 32K context), `consolidation_max_file_bytes` 262144 (larger files go to no lane: `consolidation.file_skipped_too_large`), `consolidation_max_batches_per_lane` 20 (the rest: `consolidation.batches_deferred`), `consolidation_changed_files_first` true. The rewrite-key bound (FIX-P-7) applies per batch, plus a cross-batch duplicate check: a breach still rejects the night. A batch whose answer is malformed (a JSON cut by the output cap) is dropped alone (`consolidation.batch_dropped`) and the other batches still land. If the local model goes away mid-lane, the batches validated before it are kept, the remaining secret-lane files stay untouched (never the cloud), the Turkish notice goes out and `consolidation.local_unavailable` carries `completed_batches` and `remaining_files`. Branch, commit and pending stay one per night. The per-call bounds were raised so a full answer can finish: 5 minutes per cloud batch (was 2) and per warm local call (was 60 s).
   **Post-review note (FIX-B-5 phase 2, decision G06-6):** the answer no longer echoes untouched files. Each entry is `{"status": "unchanged"}` (left out of the rewrite map, so the file keeps its bytes) or `{"status": "rewrite", "content": "<whole file>"}`; the v1 plain string is still accepted. Anything else (a `"patch"` status - the patch format stays disabled -, an unknown or missing status, `null`) makes the answer malformed and only that batch is dropped. The key bound covers `unchanged` entries too. The envelope schema is `consolidation_rewrite_v2` (docs/ipc.md `schema` row). The batch budgets stay at 24000/5000: a batch whose every file is rewritten still answers in full.
   **Post-review note (FIX-B-5 phase 3):** every night that ran its batches ledgers `consolidation.run_summary{files, batches, deferred, cloud: {...}, local: {...}}` (JSONL `consolidation_run_summary`; per lane: files, sent_files, batches, completed, dropped, est_tokens_in, bytes_out, skipped, deferred, remaining), also when it ends without a diff. The next night reads the latest summary's trace back as a rolling cursor: the secret-lane files the local model did not reach (`consolidation.local_unavailable` remaining_files), then the files beyond the cap (`consolidation.batches_deferred` files), both ledgered in packing order. Those files come first (before the changed files) and keep that order, so the night continues where the last one stopped and the files it sent join the back: a corpus larger than one night's cap rotates through every file in ceil(files / files per night) nights, a file changed every day included. `kahya consolidation show` prints `Bu gece: %d dosya, %d parça; %d dosya ertelendi` (the pending night's files consolidated, batches, deferred files) above the diff; GET /v1/consolidation carries it as `summary`.
5. Enforce the skip rule Go-side: any hunk overlapping a user-touched line from step 3 is dropped before staging (user_edit wins).
   **Post-review note (FIX-P-10):** the line diff's LCS table is bounded (one flat int32 table of at most 4M cells, about 16 MB). A file whose table fits gets the exact diff as before (same hunks, same result). A larger file is trimmed to the region between its common prefix and suffix; if that region still does not fit it becomes one coarse hunk, so a single user-touched line anywhere in it keeps the whole region original (JSONL `consolidation_diff_coarse_fallback{path, orig_lines, proposed_lines}`).
6. Run hot-window pass: episodes older than 90 days and not yet cooled → promote detail atoms (sayı/tarih/alıntı/karar/söz) to `agent_derived` candidate facts via kahyad's fact-write path; only then mark cooled. Summaries must cite episode/chunk ids as raw evidence.
7. Commit on the branch as `author=kahyad`. Suggestion mode: store pending-diff state, notify (Telegram, redacted per W5-01 rules): `"Konsolidasyon önerisi hazır — kahya consolidation show"`. Auto mode (guarded): merge to main directly.
   **Post-review note (FIX-P-12):** both modes ledger `consolidation.pending` first; a failed pending write removes the branch and worktree and fails the run. Auto mode then merges through the same path as approve, whose `consolidation.approved` row resolves that pending row; if the merge fails, the suggestion stays pending (`kahya consolidation approve` retries it, the next night supersedes it) and the Turkish notice `Otomatik konsolidasyon birleştirilemedi — öneri bekliyor: kahya consolidation show` goes out.
8. On `kahya consolidation approve`: merge to main, delete worktree/branch, trigger `kahya reindex` (kahyad-internal call — the session never touches brain.db), then run the W4-06 nightly `git push`. On reject: delete branch, ledger the rejection.
9. Register the 03:00 job; add `kahya job run nightly-consolidation` manual trigger.
10. Write the tests in Deliverables; wire into `make test`.
